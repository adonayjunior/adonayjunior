## From operational problem to product outcome

My work does not start with a framework. It starts with an operation, a user and a result that matters.

**Operational context → problem framing → discovery hypothesis → MVP → architecture → delivery → evidence → next decision**

That loop shapes the projects below. The repositories are not only technical demonstrations: the main cases document product vision, users, trade-offs, success metrics, risks and evolution paths alongside working software.

| Product lens | Questions I make explicit |
|---|---|
| **Value** | Who has the problem, how painful is it and what outcome should change? |
| **Viability** | Which business rules, risks and constraints define the real solution space? |
| **Feasibility** | What is the smallest architecture that is safe now and evolvable later? |
| **Evidence** | Which leading metrics, outcomes and guardrails tell us whether to continue? |

## The engineering journey: foundations to modern systems

Technology changes; the fundamentals do not. I learned through explicit control flow, records, files, constrained environments and direct feedback. I revisited those roots not as nostalgia, but to show the continuity between yesterday's fundamentals and today's systems engineering.

**Pascal and BASIC taught structure and constraints → C++ deepened algorithms and memory awareness → .NET and Java became platforms for business systems → Python expanded analytics and AI → Go and Rust brought the journey into modern concurrency, reliability and performance.**

| Project | Era and stack | What it preserves or explores |
|---|---|---|
| [**pascal-manifest-validator**](https://github.com/adonayjunior/pascal-manifest-validator) | Free Pascal | Records, units, file processing and deterministic validation, backed by FPCUnit tests. |
| [**basic-retro-arcade**](https://github.com/adonayjunior/basic-retro-arcade) | QB64 Phoenix Edition | Pong and Snake, persistent scores, separated game logic and automated checks. |
| [**cpp-projects**](https://github.com/adonayjunior/cpp-projects) | C++ | Data structures, algorithms, CMake and CI: the mechanics underneath higher-level systems. |

| [**go-service-sentinel**](https://github.com/adonayjunior/go-service-sentinel) | Go | Goroutines, cancellation, bounded concurrency and service reliability. |
| [**rust-log-inspector**](https://github.com/adonayjunior/rust-log-inspector) | Rust | Ownership, typed errors, streaming processing and a compact optimized CLI. |
